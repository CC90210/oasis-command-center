# THE APP IS PRIVATE; THE MARKETING SITE IS NOT.
# Almost every path here is an authenticated operator surface holding merchant
# PII. So the posture is default-deny: `Disallow: /` first, then allow back the
# nine public marketing pages by name. Adding a page to lib/marketing/routes.ts
# does NOT publish it to crawlers — this file has to say so too, and
# tests/robots-tiers.test.ts fails if the two drift apart.
#
# 🚨 THE NAMED-GROUP TRAP, WHICH IS WHY THIS FILE LOOKS REPETITIVE
# A crawler that matches a named `User-agent` group ignores `User-agent: *`
# ENTIRELY. It does not merge, it does not inherit. So a tier-2 group written as
# the obvious two lines:
#
#     User-agent: GPTBot
#     Allow: /
#
# does not mean "GPTBot is welcome on the public pages". It means "GPTBot may
# crawl the entire authenticated application", because every Disallow in the
# wildcard group vanished for that one crawler. The full rule set is therefore
# RESTATED verbatim in every named group. Do not "tidy" this into one group.
#
# Content-Signal (contentsignals.org, draft) is a stated preference, not
# enforcement. It does not block anything and must never be described to a
# client as blocking AI training.
Content-Signal: ai-train=no, search=yes, ai-input=yes
